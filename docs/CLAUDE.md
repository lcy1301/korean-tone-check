# 한국어 작성·교정 기준

한국어 제품 문구와 설명문에는 아래 기준을 적용한다. 기존 글을 교정할 때에는 의미와 사실을 보존하고, 새 글을 작성할 때에도 출력 전에 이 기준으로 검사한다.

## 권장 표현

- 기능·설정이 `붙습니다` → `적용됩니다`, `따라붙습니다` → `함께 적용됩니다`.
- 기능을 `얹습니다` → `추가합니다`, 요소를 `걷어냅니다` → `제외합니다`.
- 결과물을 `굽습니다` → `만듭니다`, 분류의 `갈래` → `종류`.
- `PC에 안 닿음` → `PC에 연결할 수 없습니다`, `다시 잇는 중` → `다시 연결하는 중`.
- 소프트웨어의 `새 판·지금 판·판 번호` → `새 버전·현재 버전·버전 번호`. 갱신 동작은 `업데이트`.
- `적으세요·적어 주세요` → `작성하세요`. 숫자·코드 등은 `입력하세요`.
- `하실 수 있습니다` → `할 수 있습니다`, `주시기 바랍니다` → `~하세요`.
- 불필요한 `우리 서버·우리가`는 생략하거나 기능·대상을 주어로 문장을 다시 쓴다.
- 처리 상태의 `도는 중` → `처리 중`, `태그 뽑기` → `태그 생성`, 콘텐츠의 `손질` → `편집`.
- `태그가 붙습니다` → `태그가 추가됩니다`. 태그를 만드는 동작은 `태그 생성`으로 설명한다.
- 파일을 `받다·내려받다·다시 받다` → `다운로드하다·다시 다운로드하다`. `ZIP 파일로 묶어 내려받다` → `ZIP 파일로 압축해 다운로드하다`.
- 화면 항목을 `고르다` → `선택하다`, 설정값·숫자·코드를 `넣다` → `입력하다`.
- 기능·항목을 `더하다` → `추가하다`, 데이터·항목을 `지우다` → `삭제하다`.
- `연결이 돌아오면` → `다시 연결되면`. 시드 설명의 `매번 무작위 값이 쓰이고` → `생성할 때마다 무작위 시드가 적용되고`.
- 문서 내용을 `손보다` → `수정하다`. 제품을 `더 편하게 쓰실 수 있도록 다듬어 가겠습니다` → `더 편리하게 사용할 수 있도록 개선하겠습니다`.
- 문서·코드·내용을 `훑다·훑어보다·훑어 주세요` → `검토하다·검토해 주세요`. `빠르게·간단히` 등 검토 범위와 깊이를 나타내는 조건은 유지한다.
- 로라 설명의 `화풍이 서로 부딪혀` → `여러 로라의 효과가 충돌해`, `화풍이 지나치게 강하게 들어가는 경우` → `화풍이 지나치게 강하게 적용되는 경우`. 원문에 없는 충돌이나 효과를 추측하지 않는다.
- `올려 보시길 권해 드립니다` → `높여 보세요`. 결과를 확인하거나 조금씩 조절하라는 조건은 유지한다.
- 제품 안내의 `화면 뒤에서 기능이 움직입니다·기능이 질문에 답합니다`는 실제 기능·역할·처리 과정으로 설명한다.
- 문구·문서·오류의 `고치다` → `수정하다`. `고칩니다·고쳐 주세요`도 `수정합니다·수정해 주세요` 등으로 바꾼다.
- 대상을 빼는 뜻의 `좁히다` → `제외하다`. 무엇을 제외하는지 명확하게 문장을 다시 쓴다.
- 자동 기능을 `저절로 찾…·읽고 골랐…`처럼 사람에 빗대지 말고 실제 기능을 `자동으로 찾습니다` 등의 표현으로 설명한다.
- 생성 설정의 `씨앗` → `시드`, `나레이션` → `내레이션`.
- `받는 곳 열기` → `다운로드 페이지 열기`. 이용권 활성화 코드의 `제품키` → `이용권 코드`.
- `PC 에·시드을·로라 와` → `PC에·시드를·로라와`. 다른 표현도 조사 선택과 띄어쓰기를 점검한다.
- 제품 홍보의 `무검열·제약 없음·제한 없음·무제한`은 삭제하거나 확인된 실제 조건으로 설명한다.
- 사용자용 문구의 `(준비 중)` 노출과 근거 없는 성능 비교는 삭제한다. 화면을 검사하는 요청에서는 삭제할 위치를 제안한다.

## 문맥과 의미 보존

표현을 찾은 뒤 주체·대상·동작과 주변 문맥을 확인한다. 권장 표현과 뜻이 같은 경우에만 수정한다. 의미가 달라지거나 판단이 불확실하면 원문을 유지하고 `확인 필요`로 표시한다. 주체·대상·조건·부정·가능 여부·의무와 권고의 강도·수치·시점·동작 순서를 보존한다.

다운로드·선택·입력·추가·삭제 용어는 제품 문구와 기능 설명에 적용한다. `연결 코드를 받으세요`, `반죽에 버터를 넣으세요`, `책상 위 먼지를 지우세요`는 이 규칙으로 바꾸지 않는다. 수학적 덧셈이나 일반 작문의 단어도 일괄 치환하지 않는다.

제품 사용 안내는 실제 기능과 동작을 먼저 설명한다. 기술 동작을 대신하는 비유는 확인된 처리 관계로 바꾼다. 비유를 요청한 글이나 이해에 필요한 비유는 유지할 수 있다. 원문에 없는 구현 방식을 추가하지 않는다.

기계적으로 전체 치환하지 않는다. 활용형·조사·문장 구조까지 자연스럽게 고친다. 책의 판 번호, 음식 굽기, 식물 씨앗, 물리적으로 붙는 물건 등은 유지한다. 실제 제품 라이선스 키를 이용권 코드로 바꾸지 않는다.

`고치다`보다 `수정하다`, `좁히다`보다 `제외하다`를 선호한다. 실제 기계 수리나 질병 치료는 의미에 맞게 유지하거나 수리·치료로 표현한다. 실제 폭·범위 축소의 `좁히다`는 유지한다. 제외할 대상을 알 수 없으면 추측하지 않고 확인 필요로 표시한다.

예: `검색 범위를 좁히세요`는 유지한다. `품절 상품을 빼서 후보를 좁히세요`는 `품절 상품을 후보에서 제외하세요`로 수정한다.

주어 삭제로 책임이나 대상이 모호해지면 주어를 유지한다. 코드·URL·식별자·제품명·인용은 보존한다. 정책·계약의 조건 설명을 홍보 문구로 판단해 삭제하지 않는다. 사실 확인이 필요한 부분은 표시하고, 근거·수치·기능·조건을 추측하지 않는다.

## 프런트엔드 화면의 정보와 표현 형식

화면 작성·구현과 UI 문구 검사에 적용한다. 사용자의 행동, 상태 이해, 선택, 오류 해결에 필요한 정보만 표시한다. 구현 메모, 디자인 의도, 제작 과정, 컴포넌트 구조, 사용 기술 소개, 개발자에게 하는 안내는 필요한 경우 코드 주석이나 개발 문서에 둔다.

`이 영역은 사용자의 편의를 위해 카드 형태로 구성했습니다`, `추후 API를 연결할 예정입니다`, `SVG 아이콘을 사용했습니다` 같은 문구는 사용자 화면에서 삭제한다. 제목·버튼·상태와 같은 내용을 반복하는 설명도 삭제한다. 실제 조작 방법, 처리 결과, 가격·사용량·기능 제한, 동의·권한·보안 조건과 오류 해결 방법은 유지한다.

정보의 역할에 맞는 형식을 사용한다.

- 상태·등급·분류는 `연결됨`, `처리 중`, `프로` 같은 알약 형태 배지나 짧은 텍스트.
- 행동은 `다운로드`, `다시 연결`, `설정 저장` 같은 짧은 버튼 문구.
- 선택지는 의미가 분명한 선택 컨트롤과 라벨. 상태 배지와 조작 요소를 혼동하지 않게 한다.
- 조건·속성은 라벨·값, 목록, 비교표. 필요한 설명은 짧은 요약문.
- 익숙한 의미는 SVG 아이콘으로 표현할 수 있다. 뜻이 불명확하면 짧은 텍스트를 함께 표시한다.
- 세부 설명은 도움말이나 펼쳐 보기로 제공할 수 있다. 필수 조건은 숨기지 않는다.
- 오류는 문제와 다음 행동을 짧게 설명한다. 원인과 복구 방법을 배지 하나로 대체하지 않는다.

아이콘만 있는 버튼에는 접근성 이름을 제공하고 실제 버튼 요소를 사용한다. 장식용 SVG는 보조 기술에서 숨긴다. 색상만으로 상태를 전달하지 않고 중요한 안내를 툴팁에만 두지 않는다.

요약할 때 조건·단위·기간·수치·부정·오류 해결 순서를 보존한다. 모든 문장을 배지나 아이콘으로 바꾸지 않는다. 일반 문서나 장문 설명 요청에는 UI 압축 규칙을 적용하지 않는다.

문구만 받았다면 표현 형식을 제안하고, 구현 요청이면 기존 컴포넌트와 디자인 스타일을 사용해 필요한 부분만 수정한다. 요청하지 않은 기능이나 화면은 추가하지 않는다. 실제 화면을 확인할 수 있다면 넘침·중복·라벨을 확인하고, 구현했다면 접근성 이름과 키보드 조작도 확인한다. 확인하지 못한 동작을 검증했다고 주장하지 않는다.

## 검사 요청의 출력

교정문과 변경 내역을 제공한다. 변경 내역에는 각 위치의 원문, 수정문, 이유를 포함한다. 같은 문제가 여러 번 나오면 모든 위치를 기록한다. 불확실한 부분은 `확인 필요`로 표시한다. 교정문만 요청하면 교정문만, 검사만 요청하면 수정 후보만 제공한다.

변경 내역과 확인 필요 항목을 구분한다. 확인 필요 항목에는 유지한 원문과 판단에 필요한 정보를 적는다. 검토 과정에서 의미 변화가 발견되면 원래 의미를 보존하도록 되돌린다.

UI 교정은 문구 삭제·요약·배지 전환·아이콘 전환도 변경 내역에 기록하고 이유를 설명한다.

교정 후 원문과 대조해 사실·부정·가능 여부·조건·수치가 유지되는지 확인한다. 삭제한 홍보 주장과 준비 중 안내는 변경 내역에 남긴다. 사용자 기준에 없는 말투를 임의로 금지하지 않는다.
